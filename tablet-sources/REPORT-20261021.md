# Laptop/tablet report review — 21 October 2026

Reviewed `macos-20261021-130735-laptop` and `macos-20261021-130812-tablet` from the USB. Neither establishes an orientation or mode-switch value.

- All six named ACPI query files in each report are empty, despite exit=0. Old collector incorrectly treated a successful ioreg invocation as evidence of device presence. It queried IOService names rather than enumerating the ACPI plane. This has been corrected; empty data is not a tablet state.
- No sensor usage page (0x20) found in the saved IOHID device trees. The observed differences are event timestamps, queues, counters and idle time, not a hinge/orientation reading.
- Old framebuffer class lookup was also wrong (`NMXIntelVGAFB` vs `NMXVGAFB`). Its empty result cannot establish that graphics were unaccelerated.
- Linux separately confirms PCI ISH 8086:7e45 and four 8087:0ac2 HID sensor devices. Their transport is ISHTP over the PCI sensor hub, not the Wacom or ELAN I2C controller. Simply enabling VoodooI2C's sensor personalities cannot supply this transport.
- Existing local VoodooI2CHID source commit a478fd605043989269584a73e23a15cc78994f5b contains a basic I2C accelerometer rotation callback, but its quaternion handler is commented out and it is not a Meteor Lake ISH transport. Do not enable its unvalidated rotation callback on a guessed sensor.
- Firmware VGBS maps EC 0x39 lower two bits into flag 0x40. CIND _STA gates IUCE on BMID==2 and OSYS. Therefore a raw clear bit without validating the firmware enable state cannot justify disabling input.

The compiled `latitude-tablet-state` tool reports ACPI-plane inventory, IOHID sensor devices, and display rotation, with explicit unknown tablet state. It does not evaluate ACPI methods, disable devices, alter display transforms, or request input permissions. It is now included in the desktop failure collector, so the next ordinary report includes this inventory.

Automatic rotation, touch/pen coordinate alignment, and automatic built-in input suppression are NOT implemented/enabled. Required next evidence is sensor report descriptors plus orientation samples from Linux, or a verified macOS ISH sensor transport. Run the existing Linux collector in laptop, tablet, portrait-left and portrait-right positions; do not rerun the old macOS snapshots expecting orientation data they cannot provide. No extra graphics suites are needed.

Sources inspected: Linux `drivers/hid/intel-ish-hid/ipc/pci-ish.c`, `drivers/platform/x86/intel/hid.c`; YogaSMC README; VoodooI2CHID sensor source. No ready Meteor Lake ISH macOS driver was verified during this research.
